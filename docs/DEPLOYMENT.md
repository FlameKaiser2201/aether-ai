# Deployment guide

AETHER is a two-service monorepo:

- **API** — FastAPI + PostgreSQL (+ optional Redis, Supabase Storage)
- **Web** — Next.js 15 (Auth.js server-side session, proxies API calls)

Deploy both, or run the complete stack with Docker Compose. The web tier must be
able to reach the API URL from its **server** environment; browser traffic goes
through the same-origin `/api/proxy` route.

---

## 1. Prepare secrets

Generate independent secrets for every value:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"   # JWT_ACCESS_SECRET
python -c "import secrets; print(secrets.token_urlsafe(48))"   # JWT_REFRESH_SECRET
python -c "import secrets; print(secrets.token_urlsafe(48))"   # INTERNAL_API_SECRET
python -c "import secrets; print(secrets.token_urlsafe(48))"   # AUTH_SECRET
```

Production guardrails reject:

- JWT or internal secrets shorter than 32 characters or containing `change-me`
- `CORS_ORIGINS=*`
- `COOKIE_SECURE=false`
- `SEED_DEMO=true`

Set `ENVIRONMENT=production` to activate these checks.

## 2. Docker Compose (full stack)

Requirements: Docker Engine 24+ with Compose v2.

```bash
cp .env.example .env
# edit secrets, provider keys and optionally Supabase
docker compose up --build -d
docker compose logs -f api
```

Services:

| Service | Port | Notes |
| --- | --- | --- |
| `web` | 3000 | Next.js standalone server |
| `api` | 8000 | FastAPI, runs `alembic upgrade head` on boot |
| `db` | 5432 | PostgreSQL 16 with persistent volume |
| `redis` | 6379 | Redis 7 with AOF persistence |

Open <http://localhost:3000>. The API health probe is
<http://localhost:8000/health>.

Useful commands:

```bash
docker compose ps
docker compose logs -f web
docker compose exec api alembic current
docker compose exec api alembic upgrade head
docker compose down            # keep data
docker compose down -v         # delete volumes (destructive)
```

### Production notes

- Put a TLS-terminating reverse proxy or managed load balancer in front of the
  stack. Set `COOKIE_SECURE=true`, `TRUST_PROXY_HEADERS=true`,
  `ENABLE_API_DOCS=false`, `SEED_DEMO=false`, and `AUTO_CREATE_TABLES=false`.
- Update `AUTH_URL` / `NEXTAUTH_URL` to the public HTTPS origin.
- Update `API_URL` for the **web** service to the API's internal address
  (`http://api:8000`) or public HTTPS origin.
- Back up the PostgreSQL volume and the `aether_storage` volume (or use
  Supabase Storage).
- The API image runs as an unprivileged user and includes a health check.
- Scale the API horizontally behind a load balancer; use managed PostgreSQL and
  Redis when running more than one replica.

## 3. Render

The repository includes [`render.yaml`](../render.yaml) for a Render Blueprint.

### Blueprint flow

1. Push the repository to GitHub.
2. In Render, choose **New → Blueprint** and select the repository.
3. Render creates:
   - `aether-db` (PostgreSQL)
   - `aether-api` (Docker, `apps/api/Dockerfile`, context `apps/api`)
   - `aether-web` (Docker, `apps/web/Dockerfile`, context `apps/web`)
4. Set the prompted secrets (`sync: false`) in the dashboard: provider keys,
   `TAVILY_API_KEY`, voice keys, and optionally Supabase.
5. Update the hard-coded service hostnames in `render.yaml` if your service
   names or regions differ:
   - API `APP_URL`, `API_URL`, `CORS_ORIGINS`, `TRUSTED_HOSTS`
   - Web `AUTH_URL`, `NEXTAUTH_URL`, `API_URL`

The API normalizes Render's `postgresql://` connection string to
`postgresql+asyncpg://` automatically. The Docker command applies Alembic
migrations before starting Uvicorn.

### Optional Redis

Create a Render Key Value instance and set `REDIS_URL` on `aether-api`. Without
it, the API uses its in-process limiter/cache, which is fine for a single
instance but not shared across replicas.

### Notes

- Free web services sleep after inactivity; use a paid plan for always-on voice
  and chat.
- `AUTH_SECRET` is generated by the blueprint. Keep it stable; changing it
  invalidates all sessions.
- If you attach a custom domain, update `AUTH_URL`, `NEXTAUTH_URL`,
  `CORS_ORIGINS`, `APP_URL` and `API_URL` accordingly.
- Render health check path is `/health` for the API and `/` for the web tier.

## 4. Railway

Railway can deploy both services from one repository.

### API service

1. **New Project → Deploy from GitHub repo**.
2. Add a service and set the **root directory** to the repository root.
3. Railway reads [`railway.json`](../railway.json), which builds
   [`infra/railway/Dockerfile`](../infra/railway/Dockerfile) with the monorepo
   root as context.
4. Add PostgreSQL (and optionally Redis) from the Railway marketplace.
5. Set environment variables:

```text
ENVIRONMENT=production
DATABASE_URL=${{Postgres.DATABASE_URL}}       # normalized automatically
REDIS_URL=${{Redis.REDIS_URL}}                 # optional
JWT_ACCESS_SECRET=…
JWT_REFRESH_SECRET=…
INTERNAL_API_SECRET=…
APP_URL=https://<web-domain>
API_URL=https://<api-domain>
CORS_ORIGINS=https://<web-domain>
TRUSTED_HOSTS=<api-domain>
COOKIE_SECURE=true
AUTO_CREATE_TABLES=false
ENABLE_API_DOCS=false
SEED_DEMO=false
```

The container command runs `alembic upgrade head` with retries and then starts
Uvicorn on Railway's `$PORT`.

### Web service

1. Add another service from the same repository.
2. Set the **root directory** to `apps/web`.
3. Railway reads [`apps/web/railway.json`](../apps/web/railway.json) and builds
   `apps/web/Dockerfile`.
4. Set:

```text
AUTH_SECRET=…
AUTH_URL=https://<web-domain>
NEXTAUTH_URL=https://<web-domain>
API_URL=https://<api-domain>
NODE_ENV=production
```

5. Generate a public domain for both services and update the URLs above.
6. Health check: `/health` for the API, `/` for the web tier.

Railway's private networking can replace the public API URL with the internal
service address, for example `http://aether-api.railway.internal:8000`. Keep
`API_URL` server-side only.

## 5. Vercel (web tier)

Vercel hosts the Next.js app; deploy the FastAPI API on Render, Railway, Fly.io
or any container platform.

1. Import the repository into Vercel.
2. Set **Root Directory** to `apps/web`.
3. Framework preset: **Next.js**. Build command: `npm run build`. Install:
   `npm ci`.
4. Add environment variables for **Production** and **Preview**:

```text
AUTH_SECRET=…
AUTH_URL=https://your-app.vercel.app
NEXTAUTH_URL=https://your-app.vercel.app
API_URL=https://your-api.example.com
```

5. Deploy. Auth.js uses the encrypted JWT session cookie; no database is needed
   on the Vercel side.
6. If you use a custom domain, update `AUTH_URL` and `NEXTAUTH_URL`.

Notes:

- `apps/web/vercel.json` pins the framework and adds immutable caching for
  static assets.
- Do not set `API_URL` as `NEXT_PUBLIC_*`; it must remain server-side.
- Vercel serverless functions have no persistent local filesystem. Use Supabase
  Storage (or another object store) for uploads, not `STORAGE_BACKEND=local`.
- The API must allow the Vercel origin in `CORS_ORIGINS` only if browsers call
  it directly. The normal proxy path is same-origin and does not require CORS.

## 6. Cloudflare Workers (web tier)

The web app uses [OpenNext](https://opennext.js.org/cloudflare) to run on
Cloudflare Workers. Configuration lives in:

- `apps/web/wrangler.jsonc`
- `apps/web/open-next.config.ts`
- `apps/web/package.json` scripts

### First deploy

```bash
cd apps/web
npm ci

# Non-secret runtime variables
npx wrangler secret put AUTH_SECRET
npx wrangler secret put API_URL
npx wrangler secret put AUTH_URL
npx wrangler secret put NEXTAUTH_URL

npm run deploy:cloudflare
```

Alternatively, put `API_URL`, `AUTH_URL` and `NEXTAUTH_URL` in the `vars`
section of `wrangler.jsonc` and keep only `AUTH_SECRET` as a secret. Never commit
real secrets.

Local preview:

```bash
cd apps/web
npm run preview
```

Notes:

- `nodejs_compat` and `nodejs_compat_populate_process_env` are enabled so
  Auth.js and server code can read `process.env`.
- Workers have no persistent disk. Use Supabase Storage for files.
- The API stays on a container platform (Render, Railway, Fly.io, etc.);
  Cloudflare only hosts the Next.js web tier.
- Set `API_URL` to the public HTTPS API origin. Workers can reach it over the
  public internet.
- Update `AUTH_URL` / `NEXTAUTH_URL` to the `*.workers.dev` or custom domain.
- Check the OpenNext and Wrangler compatibility dates when upgrading Next.js.

## 7. Supabase Storage

1. Create a Supabase project.
2. Create a **private** bucket, for example `aether-files`.
3. Copy the project URL and the **service role** key (server-only) into:

```text
STORAGE_BACKEND=supabase
SUPABASE_URL=https://<project>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=…
SUPABASE_BUCKET=aether-files
```

The service role key bypasses row-level security, so it must never reach the
browser. AETHER stores files under `userId/fileId.ext` and deletes them when the
user deletes the file or account. If Supabase is not configured, the API uses
`STORAGE_DIR` (a local volume) instead.

## 8. Database migrations

Alembic owns the schema.

```bash
cd apps/api
alembic upgrade head
alembic current
alembic history
```

Create a migration after changing models:

```bash
alembic revision --autogenerate -m "describe the change"
# review the generated file before committing
alembic upgrade head
```

Production:

- Set `AUTO_CREATE_TABLES=false`.
- Run `alembic upgrade head` during release, or rely on the Docker image's
  startup command.
- Back up the database before destructive migrations.
- Never edit an applied migration; add a new one.

SQLite is supported for local development and tests only. Use PostgreSQL for
production concurrency, backups and managed operations.

## 9. Production checklist

- [ ] All secrets are unique, 32+ characters, stored in the platform secret
      manager, and rotated on a schedule.
- [ ] `ENVIRONMENT=production`, `COOKIE_SECURE=true`, `ENABLE_API_DOCS=false`,
      `SEED_DEMO=false`, `AUTO_CREATE_TABLES=false`.
- [ ] `AUTH_URL` and `NEXTAUTH_URL` match the public HTTPS origin.
- [ ] `CORS_ORIGINS` lists exact origins (no `*`).
- [ ] `TRUSTED_HOSTS` lists the API hostname(s).
- [ ] `TRUST_PROXY_HEADERS=true` only behind a trusted proxy.
- [ ] PostgreSQL backups and point-in-time recovery are enabled.
- [ ] Redis is configured for multi-replica rate limiting (optional).
- [ ] Supabase Storage is configured if the web tier is serverless.
- [ ] Provider keys are scoped and have spend limits.
- [ ] `/health` and `/api/v1/health/ready` are monitored.
- [ ] Logs are collected and request IDs are searchable.
- [ ] Account deletion and memory wipe have been tested.
- [ ] Rate limits fit expected traffic.
- [ ] Dependencies are updated and `npm audit` / `pip-audit` are reviewed.

## 10. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `400 Invalid host header` | `TRUSTED_HOSTS` missing the public hostname | Add the API hostname (no scheme, no path) |
| Browser CORS error | Direct cross-origin call and origin not listed | Use `/api/proxy` or add the exact origin to `CORS_ORIGINS` |
| `401` loop in the web app | `AUTH_SECRET` differs between replicas, or `API_URL` is wrong | Keep `AUTH_SECRET` identical and check server logs |
| `UntrustedHost` from Auth.js | `AUTH_URL`/`NEXTAUTH_URL` does not match the request origin | Set both to the public HTTPS URL |
| `database migration failed after 30 attempts` | Wrong `DATABASE_URL`, DB asleep, or TLS issue | Check the connection string and provider status |
| `asyncpg` cannot parse `sslmode` | Managed URL uses libpq query parameters | Use the provider's internal URL or configure `ssl` explicitly |
| Uploads fail on Vercel/Cloudflare | No persistent local disk | Configure Supabase Storage |
| Voice recording does nothing | Browser permission denied or unsupported browser | Allow microphone access; use Chrome/Edge; server STT is optional |
| Answers say "demo mode" | No AI provider configured | Add a provider key or enable Ollama |
| Research returns no sources | No search provider configured | Add Tavily/Brave/Serper/SearXNG |
| `429` responses | Rate limit reached | Wait for `Retry-After` or raise limits |
| Next.js build fails on Node 18 | Node too old | Use Node 20+ (22 recommended) |
